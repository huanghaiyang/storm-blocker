# 风暴屏蔽器 · Storm Blocker

一个 Chrome 扩展（Manifest V3）：**在 B 站和 YouTube 上，按 UP 主 / 频道名字把视频从列表里直接抹掉。**

默认名单是影视飓风本体及其矩阵（团队）账号，装上就生效；名单、模式、生效站点都能在弹窗里改。

---

## 安装（未上架，用开发者模式加载）

1. 打开 Chrome，地址栏输入 `chrome://extensions/`
2. 右上角打开 **开发者模式**
3. 点 **加载已解压的扩展程序**，选择本文件夹（`storm-blocker`，即含 `manifest.json` 的那一层）
4. 打开 B 站或 YouTube 首页 —— 命中的视频会直接消失，右下角出现一行统计

> 支持 Chrome 105+（用到了 `Element.checkVisibility`，低版本会自动走兜底判断）。

## 使用

点工具栏上的扩展图标打开设置面板：

| 项目 | 说明 |
| --- | --- |
| 总开关 | 一键启用/停用，关掉立刻还原所有被隐藏的视频 |
| 拦截方式 | **整块移除**：视频卡片不占位置；**淡化留位**：留个灰块，方便看清到底拦了多少 |
| 生效站点 | 分别控制 B 站 / YouTube |
| 角标提示 | 右下角那行"已拦下 N 个视频" |
| 屏蔽名单 | 一行一个，实时保存并立刻生效 |
| 按标题关键词屏蔽 | 折叠在下面，可选功能，按视频标题匹配 |
| 导出 / 导入 | 把配置存成 JSON，方便备份或多台机器同步 |
| 恢复默认 | 一键回到出厂名单 |

面板顶部会实时显示**当前这个标签页**拦掉了几个、命中了谁（比如"命中：影视飓风、亿点点不一样"），
方便确认名单写得对不对。

## 名单写法

每行一条规则，支持：

```
影视飓风              # 普通文字：子串匹配，"影视飓风TV""影视飓风番外"都会中
亿点点不一样
飓风*                 # 通配符：整串匹配，"飓风无限""飓风工作室"命中，"小飓风"不命中
/^Time.*$/i           # 正则（斜杠包裹）：大小写不敏感
某某营销号 # 备注      # 行尾 # 后面是注释，不参与匹配
// 整行注释
#  整行注释
```

匹配时自动忽略前后空格、全角空格和零宽字符，拉丁字母不区分大小写。
写坏的正则会被当成普通文字处理，不会让整份名单失效。

## 默认名单

```
影视飓风, 亿点点不一样, 飓风无限, 时间胶囊, 风暴眼, Hsunami, 飓多多, 十个面
```

矩阵账号的名字会变，所以这里只放了比较稳的几个。**在推荐流里看到不想看的名字，
直接照抄进弹窗的名单里就行**（同名子串会一起命中）。

## 工作原理

1. `lib/blocklist.js`：名单解析 + 匹配（纯逻辑，浏览器和 Node 测试共用）
2. `content.js`：找到"视频卡片 → UP 主名字"，命中就给卡片打 `data-sb-hidden` 属性
3. `content.css`：按属性隐藏或淡化，开关状态挂在 `<html data-sb-off>` 上，切开关不需要重扫 DOM

几个关键设计：

- **打标记而不是直接删节点**。B 站和 YouTube 都是 SPA + 虚拟列表，节点会被复用/重渲染，
  直接 `remove()` 很容易被框架又插回来，或者把列表状态搞乱。
- **两遍扫描**。第一遍走站点已知的卡片 class；第二遍从"UP 主名字节点"反查卡片容器。
  站点大改版时卡片 class 可能整个换掉，但只要作者名的 class 还在就还能拦。
- **再兜底一层尺寸启发式**：作者名往上找宽度 ≥240px 的最近容器，应付完全没见过的结构。
- **"名字还没渲染出来"不写缓存**。搜索页/首页的卡片会先以骨架屏出现，名字晚一步才渲染；
  如果这时候就把卡片记成"已检查、不用管"，之后名字出来了也不会再看 ——
  表现就是**只拦掉一部分视频**。所以只有真的读到了名字/标题、且确认不命中，才允许缓存。
- **作者名里的附加信息会被切掉**：`影视飓风 · 9月16日`、`影视飓风 · 共16课时` 都能命中
  （但 `麦克阿瑟·杰克逊` 这种名字里本来就带间隔号的不会误切）。
- **名字取不到就不动手**。宁可漏杀不可错杀成"整页视频都没了"。
- 用 `MutationObserver` + 150ms 节流重扫，另加 4 秒兜底轮询；换页（SPA 路由变化）自动清空重扫。
- 只处理真正渲染出来的卡片，`display:none` 的（折叠/未展开）不参与统计。

## 开发

```bash
npm test        # 43 项自测，含用迷你 DOM 跑 content.js 主链路
npm run icons   # 重新生成 icons/*.png（纯 Node，无第三方依赖）
```

```
manifest.json          扩展清单
content.js/css         注入到 B 站 / YouTube 的脚本与样式
lib/blocklist.js       名单解析与匹配（共享）
popup/                 设置面板
icons/                 图标（由 tools/make-icons.js 生成）
tests/                 自测 + 迷你 DOM 桩
tests/fixtures/        真实页面 class 快照（改版时重新抓取）
tools/make-icons.js    手写 PNG 编码生成图标
```

`tests/dom-stub.js` 是一份刻意做得很小的 DOM 桩，够把 `content.js` 真跑起来就行。
改 `content.js` 时如果用到新的 DOM 能力，记得在桩里补一个实现，否则测试会报
"不是函数"。

**B 站/YouTube 改版后怎么办**：`tests/fixtures/` 里存着真实页面的 class 快照，
有一个测试专门比对"扩展用的选择器"和"快照里真实存在的 class"。
改版后重新抓一份页面 HTML、更新快照，测试会立刻告诉你哪个选择器已经失效 ——
不会再出现"改了但没人知道"的静默失效。

## 已知限制

- B 站/YouTube 改版频繁，选择器可能失效。失效时要靠第二遍扫描和尺寸兜底顶上，
  极端情况下仍然可能漏拦 —— 欢迎把新结构的截图/DOM 发来补选择器。
- 只处理列表页（首页、分区、搜索、推荐侧栏、动态），不处理播放页的播放器内容本身。
- 只在 `bilibili.com` / `youtube.com` 上运行；B 站 App、第三方客户端不生效。
- 屏蔽是"客户端视觉屏蔽"，不影响账号推荐算法 —— 想看更干净可以把"不感兴趣"也点一下。
